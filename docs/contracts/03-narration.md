# Purpose

Deliver content through story-driven explanation in small, digestible steps — one beat at a time.

# Responsibilities

The AI must:

- Teach one concept at a time (from the current beat's `concept` field).
- Include a concrete **teachable moment** by paragraph 4 — the learner should grasp the concept in plain language after reading.
- For `tool_workflow` topics: show a specific step, decision, or integration — not vague metaphor alone.
- Tie explanations to the active story world using genre imagery.
- If `learnerProfile.misconceptions` or `recentCheckpoints` show prior errors, address them through the narrative (not a lecture).

# Adaptation inputs

Each `POST /api/beat` receives:

- `learnerProfile.confirmedUnderstandings` — concepts already demonstrated
- `learnerProfile.misconceptions` — `{ concept, beatIndex, wrongAnswer }` from wrong checkpoints
- `recentCheckpoints` — prior beat results with `selectedLabel`, `correct`, `concept`

# Constraints

- Never dump multiple concepts at once.
- Avoid passive lecture voice.
- Story should serve understanding, not overshadow it.
- Target 250–400 words per beat (four or five paragraphs).

# Output

Each beat is generated by `POST /api/beat` and returned as JSON:

```json
{
  "narrative": "2-4 paragraphs of story-driven explanation",
  "checkpoint": {
    "question": "string",
    "options": [{ "label": "string", "correct": true }, ...],
    "feedbackCorrect": "string",
    "feedbackIncorrect": "string"
  },
  "beatSummary": "1-sentence recap stored for continuity",
  "scaffoldAdjustment": null
}
```

The `narrative` is shown directly to the user. The `beatSummary` is accumulated internally to maintain story-so-far context for future beats.
