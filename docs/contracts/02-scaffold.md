# Purpose

Create a high-level learning and story structure without filling in details.

# Responsibilities

The AI must:

- Generate an internal outline of the journey covering:
  - Key concepts (one per beat)
  - Narrative beats with genre-appropriate story hints
  - Checkpoint locations and focus areas
  - Flexibility markers for each beat
- Infer `topicType` (`concept`, `tool_workflow`, or `skill`) from subject + goals + focus
- Align complexity with age and level from Intake. Age bands: `6_10` (shortest/simplest), `11_13`, `13_17`, `18_64` (standard adult), `65_plus` (same depth, plainer jargon).
- Honor `motivation` (`curious` | `school` | `building`) as the **ending**: tour / testable unit / making something. Do not treat it as a duplicate of `learningFocus`.
- Honor `learningGoals` and `learningFocus` as primary constraints. Focus is the facet: `understanding` (what's going on) | `method` (how people do it) | `use` (help me use it) | `general`. Old values map (`concepts`→understanding, `practical`→method, `applying`→use).
- Leave room for user influence — the scaffold is a plan, not a script

# Topic types

| Type | Examples | Beat arc |
|------|----------|----------|
| `concept` | cloud computing, photosynthesis | wonder → model → mechanism → implication → synthesis |
| `tool_workflow` | Printify, Photoshop | orient → setup → integrate → apply → troubleshoot |
| `skill` | public speaking, chess | foundation → technique → practice → refinement → application |

# Constraints

- No full explanations.
- No prose-heavy storytelling yet.
- No irreversible decisions about pacing or difficulty.
- Scaffold must be revisable mid-run via `scaffoldAdjustment` from the beat endpoint.

# Input

`POST /api/scaffold` receives:

```json
{
  "subject": "string",
  "genre": "string",
  "mode": "string",
  "level": "string",
  "age": "string",
  "motivation": "string",
  "learningFocus": "understanding | method | use | general",
  "learningGoals": "optional free text from home screen",
  "authorStyle": "optional author name from the genre dropdown or type-in",
  "answers": []
}
```

# Output

The scaffold is generated by `POST /api/scaffold` and returned as JSON:

```json
{
  "subject": "string",
  "theme": { "genre": "string", "mode": "string" },
  "topicType": "concept | tool_workflow | skill",
  "learningFocus": "understanding | method | use | general",
  "learningGoalsSummary": "one sentence or empty",
  "motivation": "curious | school | building",
  "beats": [
    {
      "id": "beat_1",
      "title": "short title (<=6 words)",
      "concept": "the single key idea this beat teaches",
      "narrativeHint": "1-sentence story direction",
      "checkpointFocus": "what to test the learner on",
      "flexibility": "rigid | soft | skippable"
    }
  ],
  "estimatedBeats": 4,
  "difficultyArc": "e.g. beginner -> intermediate"
}
```

This scaffold persists throughout the session and is passed to every beat generation call. The engine (`StoryEngine`) holds the scaffold in memory and can apply adjustments (insert, annotate, skip) without replacing it.

The API also attaches (not model-generated):

- `motivation` — stamped from intake (`curious` | `school` | `building`; aliases `work`→building, `passion`→curious)
- `authorStyle` — the name the learner picked or typed
- `authorVoiceGuide` — craft traits injected into scaffold + beat prompts (curated card, expanded cache, or generic fallback)
- `authorVoiceSource` — `none` | `curated` | `cache` | `expanded` | `generic`

Unknown names are expanded once at scaffold time and stored in `data/author-voice-cache.json` (gitignored). Beats reuse `authorVoiceGuide`; they do not expand again.

# Spine (cast + through-line)

Generated once at scaffold time and reused every beat.

The **learner is the POV** (camera), not a named cast member.

```json
{
  "throughLine": "one sentence of ongoing stakes",
  "cast": [
    {
      "id": "cast_1",
      "name": "Bramble",
      "role": "gardener",
      "aspects": ["biological history of the land", "how people and plants shaped each other"],
      "voice": "patient, names old names"
    }
  ],
  "mustCover": ["cedar and people as a relationship, not a resource list"],
  "optionalPool": ["medicinal uses", "fiber and construction", "companion plants", "bioregions"]
}
```

Rules:

- Exactly **2–3 named companions**, present from beat 1. Fit this topic + goals + genre.
- Each beat covers ONE concept. Beat concepts must be distinct — do not plan two beats that only restate the same contrast (e.g. "these two progressions feel different" then "why those two work").
- For `skill` + practical/applying focus: a later beat must have the learner **do** the skill, not only hear it explained.
- Each companion owns **1–3 related facets**. Do not add a new series-regular for every optional pool item.
- Guests may appear in a scene; they are not promoted into `cast` unless the learner follows them.
- Mid-story **steer** may change the next beat's `concept`; it does not replace `cast` or `throughLine`.
